Tool Review: rawwhp

Date: February 24, 2026

Executive verdict: rawwhp is materially useful for low-level payload bring-up and VM-exit triage on Windows hosts with WHP enabled. It should be kept and improved with optional emulation callbacks and structured output.

What It Does Well

  • Very fast path from bytes-on-disk to runnable guest code without a full emulator stack.
  • Supports practical entry modes (real, unreal, protected, long) for common lab workflows.
  • Provides detailed VM-exit reporting (memory, IO, MSR, CPUID, exceptions) that helps identify exactly what host emulation is missing.
  • Keeps footprint small by mapping one minimal contiguous GPA window.

Limitations and Risks

  • No re-entrant emulation loop yet; non-success exits stop execution after reporting.
  • Real/unreal mode currently constrained to sub-1MB payload/entry/stack setup.
  • No JSON or machine-readable mode for CI ingestion.
  • Results depend on host virtualization configuration and WHP availability.

Alternatives and Tradeoffs

  • QEMU/Bochs: richer emulation and devices, but heavier and slower for simple payload smoke tests.
  • WinDbg/kernel debugging paths: deeper system introspection, but higher setup overhead for quick raw-binary execution checks.
  • Hyper-V VM workflows: production-like environments, but overkill for tiny one-file payload tests.
  • Custom harness inside existing OS VM: more context, less control over exact initial CPU state than this tool's direct register setup.

Compared with debugger/IDE-native workflows, rawwhp is not redundant: it occupies a narrow but valid niche for early-stage instruction-level bring-up.

Workflow Fit

  • Local debugging: good first-stage check before switching to richer debuggers.
  • Incident/forensics labs: useful to test tiny suspect stubs in an isolated minimal guest context.
  • Automation: possible today via exit codes and text logs; better with future JSON output.

Evidence Snapshot

  • rawwhp --help exposes mode/address options and alias compatibility.
  • Fixture executions demonstrate parse coverage and host capability checks.
  • Exit reports include enough fields (RIP/RSP/RFLAGS + reason-specific context) for follow-up tooling.

Final Recommendation

Recommendation: improve. Keep the tool, then add optional emulation callbacks and a structured output mode for automation-heavy users.
