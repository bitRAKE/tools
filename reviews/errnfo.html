Tool Review: errnfo

Date: February 6, 2026

Executive verdict: errnfo is a legitimately useful CLI for Windows error triage and message-table discovery. It is not redundant with common shells, but it should add machine-readable output and curated module-list workflows.

What It Does Well

  • Decodes HRESULT, NTSTATUS, and Win32 values in one tool with facility/severity breakdown.
  • Bridges a practical gap: system messages plus module-provided RT_MESSAGETABLE text from DLLs.
  • Includes two valuable operational modes beyond decode: scan (discovery) and dump (inspection/filtering).
  • Works well in shell workflows where a debugger is too heavy.

Limitations and Risks

  • No JSON output, so automation requires parsing human text.
  • Message quality still depends on module coverage and language resources on the local system.
  • Large scans can produce noisy output without curation.
  • Derived mappings (for example NTSTATUS to Win32) are convenience mappings, not semantic truth.

Alternatives and Tradeoffs

  • WinDbg / debugger extensions: richer context while actively debugging, but slower for quick shell-level lookups.
  • Microsoft err.exe: fast decoding, but lacks integrated message-table scan/dump workflows.
  • PowerShell / ad hoc scripts: possible with FormatMessage wrappers, but usually fragmented and less reusable.

errnfo is not superfluous; it combines capabilities that are usually scattered across debugger commands and one-off scripts.

Workflow Fit

  • Local debugging: excellent for quick error interpretation without attaching tools.
  • Incident response/forensics: useful when triaging logs with mixed error classes.
  • CI/automation: promising, but limited today by non-structured output.

Evidence Snapshot

  • errnfo hr 0x8034001B returned structured HRESULT fields plus message text.
  • errnfo nt 0xC0000241 showed NTSTATUS plus derived HRESULT/Win32 mapping.
  • errnfo w32 12029 -m wininet.dll resolved message text from module resources.
  • errnfo scan C:\Windows\System32 --paths quickly produced a module candidate list.
  • errnfo dump wininet.dll --list --grep connection --max 5 returned targeted message entries.

Final Recommendation

Recommendation: keep and improve. Priority improvements: --json, module-list file input, and quieter scan presets.
